三块可以分开部署：App 是客户端；Hub 建议跑在有 Agent CLI 的裸机 / VM；Channel 用 Docker，前面加 TLS。

Self-hosting

Three pieces, three homes: the app is a client; Hub belongs on a machine that already has agent CLIs; Channel is Docker behind TLS.

Agent Hub

编码引擎依赖本机登录态，容器里复刻全家桶成本高。生产默认：裸机 + systemd。先用要跑服务的那个用户初始化储物袋和口令，再装用户级 systemd 服务；服务会以该用户的 Hub 目录和引擎登录态运行。

Engine CLIs need host login state. Recreating that inside a container is painful. Production default: bare metal + systemd. Initialize the pouch and password as the user that will run the service, then install a user-level systemd unit; the service uses that user's Hub directory and engine logins.

systemd
cargo build --release -p shepaw-cli
sudo install -m 755 target/release/shepaw /usr/local/bin/shepaw
read -rs SHEPAW_PASS && printf '%s\n' "$SHEPAW_PASS" | shepaw init --name <name>
shepaw install-service      # 写出 shepaw-hub.service 到 ~/.config/shepaw-hub/
mkdir -p ~/.config/systemd/user
cp ~/.config/shepaw-hub/shepaw-hub.service ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now shepaw-hub
loginctl enable-linger "$USER"   # 退出登录后服务继续运行

备份整个 ~/.config/shepaw-hub/（identity、peer-devices、pouches、channel）。主机只监听 Peer 端口（默认 18793）；不要把它直接暴露到公网，外网访问走 Channel。

Back up the whole ~/.config/shepaw-hub/ (identity, peer-devices, pouches, channel). The host only listens for Peer (default 18793); do not expose that port directly to the internet — use Channel for off-LAN access.

Channel

compose
cp .env.example .env
# PORT, BASE_URL, DATABASE_URL=postgres://..., REDIS_ADDR
# 不要设 AUTH_MODE=open（或旧的 DEV_SKIP_AUTH=1）
docker compose up -d
curl -fsS https://channel.example.com/health
  • TLS 终止：Caddy / Nginx / Cloudflare；BASE_URL 用 https
  • 生产用 Postgres + Redis，不要多副本共用一个 SQLite 文件
  • 配置 ALLOWED_ORIGINS / ALLOWED_DOMAINS
  • 给 /proxy 与 /tunnel/connect 做反向代理限流
  • Terminate TLS at Caddy / Nginx / Cloudflare; BASE_URL must be https
  • Postgres + Redis in production — do not share one SQLite file across replicas
  • Set ALLOWED_ORIGINS / ALLOWED_DOMAINS
  • Rate-limit /proxy and /tunnel/connect at the reverse proxy
